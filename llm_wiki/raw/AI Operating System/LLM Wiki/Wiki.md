### 🧭 Тогда роли слоёв становятся очень чистыми

- **RAW** — первоисточник, доказательство. Не изменяется.
- **RESUME** — что конкретный источник сообщает. Сохраняет структуру и контекст **этого источника**.
- **CONCEPT** — что проект в совокупности знает о некотором понятии, независимо от того, из какого источника это знание пришло.
- **QUERY** — механизм доступа к этим знаниям.
- **INDEX** — навигация.
- **LOG** — история работы LLM.
- **SCHEMA / SKILL** — правила, по которым всё это должно работать.


1. kill discovery работает.
2. `Query` умеет находить знания.
3. `Ingest` создаёт Resume.
4. `Ingest` способен накапливать знания.
5. `Concept` может расширяться при появлении нового источника.
6. `Query` способен использовать накопленное знание.
7. `Lint` способен проверять provenance и дубликаты.


### **Главный инвариант**:

> Несколько Resume, содержащих один семантический концепт, должны сходиться в один canonical Concept, а не порождать параллельные Concept pages.**

Вот это я бы теперь назвал **следующим архитектурным checkpoint'ом**.

### Роли слоёв выглядят так

```
RAW
 │
 │  неизменяемые источники
 ▼
INGEST
 │
 ├───────────────┐
 ▼               ▼
RESUME         CONCEPTS
 │               │
 │               └── накопление знаний
 │
 └───────────────┐
                 ▼
               INDEX
```

А `queries/` находится **сбоку от этого конвейера**:

```
wiki/
├── resume/       ← что мы узнали из конкретных источников
├── concepts/     ← что мы знаем о концептах в совокупности
├── index.md      ← где это найти
├── log.md        ← что LLM делала
└── queries/      ← какие вопросы/запросы мы сохраняем
```

Например:

```
queries/
├── how-aios-memory-works.md
├── find-context-engine-decisions.md
├── compare-agent-memory-approaches.md
└── cyberlifebook-architecture.md
```

Внутри:

```
# How AIOS Memory Works

## Query

Как устроена память AIOS в CyberLifeBook и какие механизмы
Claude-Mem, LLM Wiki и Graphify выполняют в этой архитектуре?

## Scope

- [[concepts/aios]]
- [[concepts/llm-memory]]
- [[concepts/agent-memory]]

## Expected use

Используется для анализа архитектуры памяти AIOS.
```

При выполнении `query` Skill читает этот запрос, обращается к `wiki/`, синтезирует ответ — **но сам ответ не становится автоматически частью Wiki**.

Это очень хорошее разделение:

**knowledge ≠ queries ≠ query results**

И оно позволит нам позже иметь набор повторяемых интеллектуальных запросов, фактически небольшую **библиотеку исследовательских процедур для AIOS**.

### Итого

```
raw/          → Источники
resume/       → Знания из конкретных источников
concepts/     → Синтезированные накопленные знания
index.md      → Навигация
log.md        → История изменений
queries/      → Повторно используемые вопросы
schema/       → Правила поведения LLM
```
