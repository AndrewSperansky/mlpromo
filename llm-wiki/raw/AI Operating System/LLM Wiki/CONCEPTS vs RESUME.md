
# Двумерная модель WIKI


Представим два источника:

```
RAW A                         RAW B
 │                             │
 ▼                             ▼
RESUME A                      RESUME B
 │                             │
 ├─ этаж 1: Context            ├─ этаж 1: Context
 ├─ этаж 2: Context Engine     ├─ этаж 2: Graph View
 ├─ этаж 3: Neo4j              ├─ этаж 3: Context Engine
 ├─ этаж 4: GraphQL            ├─ этаж 4: PostgreSQL
 └─ ...                        └─ ...
```

Это два **вертикальных здания**. Каждый `resume` сохраняет структуру знаний **конкретного raw-источника**.

А `concepts/` строится **горизонтально**:

```
		                    CONCEPTS
		                        │
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
     Context              Context Engine                GraphQL
        │                        │                        │
        │                        │                        │
   ┌────┴────┐              ┌────┴────┐              ┌────┴────┐
   │         │              │         │              │         │
Resume A  Resume B      Resume A   Resume B       Resume A   Resume B
```

То есть:

> **Concept — это не новое гнездо знаний, параллельное Resume. Это горизонтальная агрегация одного и того же концепта, обнаруженного в разных Resume.**

И вот это уже очень хорошее архитектурное правило.

### Тогда я бы сформулировал различие так

**Resume отвечает:**

> «Что этот конкретный raw-источник говорит и какие знания в нём находятся?»

**Concept отвечает:**

> «Что проект знает об этом концепте, если посмотреть на все источники, где он встречается?»

Поэтому:

```
RAW
 │
 ├──→ RESUME A ──┐
 │               │
 └──→ RESUME B ──┼──→ CONCEPT: Context Engine
                 │
 └──→ RESUME C ──┘
```

Но важно: `Concept` **не заменяет Resume**.

`Resume` сохраняет вертикальную структуру и provenance каждого источника.

`Concept` связывает эти знания **вширь**.

---

## И здесь становится понятным то разночтение, которое ты заметил

В `AGENTS.md` сейчас написано:

> `resume/ — knowledge extracted from individual sources;`  
> `concepts/ — accumulated knowledge across multiple sources`

Это **почти описывает твою модель**, но недостаточно точно.

Проблема в слове **accumulated**.

Его можно понять как:

```
Resume
   ↓
Concept
```

то есть «собрали всё в новую страницу».

А ты имеешь в виду:

```
             SOURCE A
                │
             RESUME A
                │
                ├─────────┐
                          │
             SOURCE B     │
                │         │
             RESUME B ────┼──→ SAME CONCEPT
                          │
             SOURCE C     │
                │         │
             RESUME C ────┘
```

**Это не вертикальная трансформация. Это горизонтальная консолидация.**

Именно это, на мой взгляд, нам теперь нужно зафиксировать в архитектуре Wiki.

---

### А значит, Query становится гораздо понятнее

Query не должен мыслить так:

```
Query
 ↓
Concepts
 ↓
Answer
```

и не должен мыслить так:

```
Query
 ↓
Resume
 ↓
Answer
```

Правильнее:

```
                       QUERY
                         │
                         ▼
                  relevant concepts
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           Concept A  Concept B  Concept C
              │          │          │
              ▼          ▼          ▼
          Resume A/B   Resume B/C   Resume A/C
              │
              ▼
             RAW
```

То есть **Concepts — это индекс горизонтального знания**, а Resume остаётся вертикальной памятью источника.

Query в обычном случае должен находить **концепты**, которые отвечают на вопрос, а через их provenance при необходимости понимать, из каких Resume это знание пришло.

---

## И тогда появляется очень важный запрет

Ты фактически описал главный инвариант `concepts/`:

> 🚫 **Нельзя создавать новый Concept только потому, что тот же самый концепт пришёл из другого источника под другим названием, на другом языке или с немного иной формулировкой.**

Например:

```
Resume A:
  Context Engine

Resume B:
  Context Management Engine

Resume C:
  Движок контекста

Resume D:
  Context Executor
```

не должны автоматически становиться:

```
concepts/
├── context-engine.md
├── context-management-engine.md
├── context-executor.md
└── движок-контекста.md
```

Если семантически это **один концепт**, должен существовать:

```
concepts/
└── context-engine.md
```

а внутри него:

```
Sources
├── resume/context-engine
├── resume/architecture-context
├── ...
```

Вот теперь я понимаю, почему ты назвал это **«знания вширь»**.

### Это фактически две координаты Wiki

```
                         ГОРИЗОНТАЛЬ
                    объединение знаний
                           ───────→

                 Context Engine
                       │
                       │
                       │
                       ▼
                      ВЕРТИКАЛЬ
                 структура источника

                    RAW
                     ↓
                   RESUME
                     ↓
                 его этажи
```

И это очень полезная модель для всей дальнейшей архитектуры.

**Resume = вертикальная ось.**  
**Concept = горизонтальная ось.**  
**Raw = evidence.**  
**Query = навигация/доступ к накопленному знанию.**
