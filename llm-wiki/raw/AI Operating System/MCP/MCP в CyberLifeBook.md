# MCP в CyberLifeBook ([[AIOS]])

## Основная идея

**MCP не является транспортом и не является API к базе данных.**

MCP — это **слой возможностей (Capability Layer)**, через который AI взаимодействует с проектом.

AI работает не с GraphQL, Cypher или SQL, а с предметными возможностями системы.

---

## Роль MCP

MCP является единой точкой входа AI в проект.

Любой агент (OpenCode, ChatGPT, Codex, Hermes, локальная LLM, голосовой ассистент) работает исключительно через MCP.

```
AI Agent
    │
    ▼
   MCP
    │
    ▼
CyberLifeBook Services
```

---

## MCP ничего не знает о реализации

MCP не знает:

- Cypher;
- SQL;
- GraphQL;
- Neo4j;
- PostgreSQL.

Он знает только возможности системы.

Например:

```
createContext()
executeContext()
saveContext()
searchKnowledge()
getProjectState()
findPerson()
```

---

## Основные потребители MCP

- OpenCode
- ChatGPT
- Codex
- Hermes
- локальная LLM
- голосовой интерфейс
- будущие AI-агенты

---

## Первые сервисы MCP

На первом этапе достаточно минимального набора:

- Context Service
- Memory Service

В дальнейшем могут появиться:

- Graph Service
- Prompt Service
- Skill Service
- Project State Service
- AI Session Service
- Graphify Service
- Claude-Mem Service

Развитие MCP происходит только по мере появления устойчивых сценариев использования.

---

## Взаимодействие с Context Engine

MCP не строит контекст.

MCP лишь инициирует работу Context Engine.

```
Voice / Chat

↓

LLM

↓

MCP

↓

Context Engine

↓

ContextQuery (PostgreSQL)

↓

Neo4j

↓

Graph View
```

---

## Контекст создается AI

Одной из основных задач MCP станет поддержка генерации пользовательских контекстов.

AI формирует описание требуемого контекста.

MCP передает его Context Engine.

Context Engine использует сохраненный `ContextQuery` или создает новый.

---

## Голосовое управление

В архитектуре голосового управления MCP становится центральным координатором.

```
Voice

↓

Speech-to-Text

↓

LLM

↓

MCP

↓

CyberLifeBook
```

Таким образом голосовой интерфейс и текстовый чат используют один и тот же набор возможностей системы.

---

## Принцип развития

MCP развивается одновременно с проектом.

Не проектируется заранее целиком.

Каждый новый сервис появляется только тогда, когда возникает реальная потребность.

---

# Архитектурный принцип

> **MCP — это предметно-ориентированный слой возможностей (Capability Layer), через который AI взаимодействует с CyberLifeBook на языке намерений, а не на языке технической реализации.**

---

Мне кажется, стоит добавить еще один пункт, который мы сегодня неявно сформулировали, но он очень важен.

## MCP — стабильный контракт между AI и системой

Внутренняя реализация CyberLifeBook может меняться:

- GraphQL → REST;
- Neo4j → другая графовая БД;
- Cypher → новый движок запросов;
- изменение структуры Context Engine.

Но если возможности MCP (`executeContext()`, `searchKnowledge()`, `createContext()` и т.д.) остаются неизменными, то **ни один AI-агент не потребует переписывания**. Меняется только реализация под MCP, а не сами агенты.

Именно этот принцип, на мой взгляд, делает MCP не просто интерфейсом доступа, а **долговременным архитектурным контрактом** между AIOS и CyberLifeBook.
